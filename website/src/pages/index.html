10-Line Quickstart

Setup your payment gateway in seconds with zero boilerplate and full TypeScript autocompletion.

server.ts (Express) 
import express from "express";
import { BkashServer } from "bkash-server";
import { createExpressHandler } from "bkash-server/frameworks";

const app = express();
const bkash = new BkashServer({
  apiVersion: "v1.2.0-beta", // "v2" is experimental
  appKey: process.env.BKASH_APP_KEY!,
  appSecret: process.env.BKASH_APP_SECRET!,
  username: process.env.BKASH_USERNAME!,
  password: process.env.BKASH_PASSWORD!,
  baseUrl: process.env.BKASH_BASE_URL!,
});

// Mounts /create, /callback, /status. The amount is decided here, never by the browser.
app.use("/api/bkash", createExpressHandler(bkash, {
  resolveOrder: async () => ({ amount: 1550, currency: "BDT", invoiceNumber: "INV_1001" }),
}));

app.listen(3000);

CheckoutButton.tsx (React) 
import { useBkash, BkashButton } from "bkash-client/react";

export function CheckoutPage() {
  const { state, error } = useBkash({ createUrl: "/api/bkash/create" });

  return (
    <div>
      <BkashButton>Pay with bKash</BkashButton>
      {state === "pending" && <p>Payment pending, do not pay again.</p>}
      {error && <p>{error.message}</p>}
    </div>
  );
}

Why This Library?

How we eliminate the critical traps that cause traditional bKash integrations to fail in production.

⏱

Token Rate-Limit Shield

bKash Tokenized v2 enforces a strict limit of max 2 calls/hr to grant-token. Standard scripts make 2 calls per checkout and crash by the second user. Our SDK proactively caches tokens and rotates via refresh-token.

✓

Enforced Amount Verification

Never trust a callback blindly. Our adapters numerically verify execute amounts against initial invoices and reject manipulated transactions before firing order fulfillment events.

⚡

Idempotency & Auto-Query

Eliminates the dreaded bKash 2062 duplicate error on fast user refreshes. Automatically runs queryPayment on 30s timeouts to prevent money-deducted zombie states.
